# sheets/todo/ —— 待办弹层（`?sheet=todo`，SPEC §5.7、§9.2）

全站共用、按需加载的底部面板（`Sheet`，档位 `['content', 'large']`）：加一项待办 / 待确认 / 打包 / 要买，或者编辑、删除一项。
打开一律用 `sheets/index.js` 的帮手：

```js
import { openTodoSheet } from '../sheets/index.js';
openTodoSheet({ list: 'packing' }, { keyboard: true, trigger: e.currentTarget });           // 新建，预填清单（iOS 先叫出键盘：在点击回调里同步调用）
openTodoSheet({ list: 'confirm', bookingId: b.id }, { keyboard: true, trigger: e.currentTarget });  // 从预订「加一条待确认」
openTodoSheet({ itemId: item.id }) / openTodoSheet({ dayId: day.id });                    // 从条目 / 某一天
openTodoSheet(todo.id, { trigger: rowButton });                                            // 编辑这一项
```

谁在用：清单页点一行、打包快速添加后的「改」、＋ 面板「加待办」（`{ list: 'todo' }`）、预订详情「加一条待确认」、概览页出发前待办卡的「加一项」。

| 写法 | 意思 |
|---|---|
| `?sheet=todo` | 新建（空白，放进「待办」） |
| `?sheet=todo:l.packing` | 新建，放进打包（`l` = list：`confirm` / `todo` / `packing` / `buy`） |
| `?sheet=todo:b.<预订 id>` / `i.<条目 id>` / `y.<天 id>` | 新建并关联；只给预订、没说清单时默认放进「待确认」；只给条目时「哪天」从条目推 |
| `?sheet=todo:<id>` | 编辑这一项；找不到（对方刚删、旧链接）说「这一项找不到了」 |

| 文件 | 内容 |
|---|---|
| `TodoSheet.jsx` | 弹层（default 导出）：外层 `Sheet` + 提交按钮（`SubmitButton` 受控：文字 → 转圈 → 对勾），里面的表单按参数重建 |
| `form.js` | 纯逻辑（单元测试 `test/unit/page-lists.test.js`）：`initialForm`（编辑 / 新建预填）、`validateForm`（中文原因）、`formToValues`（写进 todos 的字段）、`isDirty`、`sheetTitle`、`linkSummaryText`（「关联」收起时的摘要） |
| `todo.css` | 样式（`.tdf*`） |

清单的文案、按名字猜分类和量词、截止时间的说法和快捷选项都在 `pages/lists/model.js`（页面和弹层共用一份）。

## 表单（从上到下）

1. **放在哪个清单**：分段控件 待确认 / 待办 / 打包 / 要买；弹层标题跟着变（「加一件要带的」「编辑待确认」……）；换了清单保存时排到那个清单最后，分类不丢。
2. **标题 + 备注**：同一块往下凹的输入区（像备忘录），聚焦一圈强调色细边；标题跟着字数长高，新建时自动聚焦，**回车直接添加**（输入法选词的回车不算）；
   空标题提交：标题框摇一下（`ui/shake.js` 的参数）+ 触感 + 红字「先写一下是什么」，按钮不转圈。
   备注里认出来的电话 / 邮箱 / 网址在输入区下面给「📞 打电话」「↗ 打开网页」「💬 写邮件 / WhatsApp」小胶囊（`pages/lists/ActionChip.jsx` 的 `NoteActions`，和清单行同一个；
   边打字边出来；只读成员也能点）——从概览、预订详情打开这个面板看详情时，也能直接打电话。
3. **分类**（只有打包）：证件 / 衣物 / 电子 / 洗护 / 药品 / 其他 + 已有的自定义分类 +「＋ 自定义」；没选时按标题猜（「按名字猜的是「电子」，点别的可以改」）。
4. **数量**（打包、要买默认有；别的清单原来有才显示）：`ui/Stepper`，量词按标题猜；从 0 开始的「＋ 加数量」。
5. **谁的东西 / 谁负责**：共用（不指定）/ Jeremy / Cathy。
6. **截止时间**：快捷「今晚 21:00」「明晚 21:00」「出发前一晚」（按行程时区；已经过了的不给）或「选日期…」→ 日期 + 钟点（选了日期钟点先填 21:00，可以改；钟点清空按 23:59）+ ×（不要截止时间）；
   日期、钟点框不要浏览器自带的小日历 / 小钟图标（英文系统的「11:59 PM」在 375 宽会被切掉），点框里任何地方都弹选择器（`showPicker()`；iOS 本来就弹滚轮）；
   下面实时说「还剩 2 天 3 小时 · 后天 18:00 前」（快到期警示色 / 红色）；设备时区和行程时区不一样时（出发前人在香港）再一行「按越南时间填（香港时间 明天 23:59）」。
7. **关联**（`ui/ExpandableCard`，交互 7）：平时收起成一行摘要（「D2 · 预订「椰影湾酒店」 · 条目「出海浮潜」」，都没有就「不关联（可以关联哪天、预订或条目）」），
   新建时表单短一截、键盘弹起时也看得到要紧的字段；点开原地展开：哪天（D1… 小胶囊，可以横滑）、预订（下拉，选了旁边「看预订」打开预订详情）、条目（按天分组的下拉，选了自动带上那天，「去看看」跳到那天并展开它）。
8. 编辑时：**已完成**（勾选框；下面写「Cathy 勾的 · 昨天 21:10」，改了写「保存后算完成」）、**删除这一项**（关面板，外壳弹「已删除 · 撤销」）。

提交：校验 → `store.insert` / `store.update`（只提交真正改了的字段）→ `await r.saved`（写进本机队列就算成功，离线也行）→ 对勾描完 → 面板收回（不再问）；
不在清单页时提示「已加到「待办」· 查看」（点了去清单页并滚到那一项）。失败：按钮变红「重试」+ 中文原因。改了一半关面板先问「放弃未保存的内容？」。

## 状态

- 行程还在读：和表单差不多高的骨架（面板按内容高度升起时，数据到了表单不会被挡在下面）；读不到：「没有读到行程」+ 原因。
- 只读成员：顶上说明「你是只读成员：只能看，不能修改。」，所有输入禁用、没有提交和删除；「关联」照样能展开看，「看预订」「去看看」照样能点。
- 编辑的那一项刚被对方删掉：顶上警示「这一项刚被删除了，改动保存不了」，提交禁用。
